Project onboarding generated by **your local AI** and shown at `/onboarding`, inside your own app.

1. `onboarding-kit` creates an `onboarding.json` with every field blank and instructions for the AI.
2. You ask the AI you already use (Claude Code, Cursor, Copilot…) to read and fill in the file.
3. `onboarding-kit` validates the result and shows a presentation of the project at `/onboarding`.

It works in almost any JavaScript project: metaframeworks, HTTP servers, Vite SPAs, mobile and desktop apps, libraries and CLIs, on **Node.js, Bun or Deno**. No runtime dependencies.

## Getting started

```bash
npm i -D onboarding-kit
npx onboarding-kit init --lang en
```

`init` detects the framework and wires the `/onboarding` route the native way:

| Project | What `init` does |
|---|---|
| **Next.js** (App Router) | creates `app/onboarding/route.ts` (or `src/app/...`); prints the snippet for the Pages Router |
| **Nuxt** | creates `server/routes/onboarding.ts` |
| **SvelteKit** | creates `src/routes/onboarding/+server.ts` |
| **NestJS** | adds `OnboardingModule.register()` to `src/app.module.ts` |
| **Vite** (React, Vue, Svelte, Solid, Preact, Qwik, Lit) and **React Router 7 / Remix** | adds the `onboarding()` plugin to `vite.config` |
| **Create React App** | creates `src/setupProxy.js` |
| **Astro, Gatsby, Express, Fastify, Koa, Hono, Elysia, AdonisJS, Webpack/Vue CLI** | prints a 2–3 line snippet to paste |
| **Angular, React Native/Expo, Electron, libraries and CLIs** | only the script below |

In every case `init` also adds an `onboarding` script to `package.json` (`npm run onboarding`, `pnpm onboarding`…) that opens the presentation at `localhost:4321` without starting the app. Use `--no-script` to skip it.

In a terminal, `init` asks which language you want (Enter = Portuguese); `--lang en` skips the question.

If detection is wrong, force it with `--framework <id>` (`next`, `nuxt`, `sveltekit`, `astro`, `remix`, `gatsby`, `nest`, `adonis`, `express`, `fastify`, `koa`, `hono`, `elysia`, `angular`, `vite`, `cra`, `webpack`, `react-native`, `electron`, `library`, `node`).

Then send this to your AI:

> Read onboarding.json and follow the instructions in "_instructions" to fill it in based on this repository. When done, run "npx onboarding-kit validate" and fix whatever it reports.

Or let the kit do it: `npx onboarding-kit init --ai` runs the installed Claude Code, Codex or Gemini CLI with the prompt and validates at the end.

Open `/onboarding` with the app running in dev, or run `npx onboarding-kit serve`. If you open it before the AI finishes, the page shows the prompt, follows the sections as they are filled in and switches to the presentation when the AI is done.

## Commands

| Command | What it does |
|---|---|
| `init` | Creates `onboarding.json` and the route. Options: `--framework`, `--lang`, `--project` (monorepo), `--people`, `--ai`, `--no-route`, `--no-script`, `--force` |
| `prompt` | Prints the text to send to the AI |
| `facts` | Facts the AI builds on: framework, UI, runtime, languages, branches, commit style, CI, hooks, PR templates, tests, monorepo subprojects, architecture signals, TODOs and notes in comments. `--project <folder>`, `--people`, `--json` |
| `validate` | Checks required fields, leftover template items, whether evidence exists, secrets, text too long for a slide, duplicates, common Mermaid mistakes, forgotten subprojects. Prints a coverage score. `--ci`, `--strict`, `--min-score <n>`, `--badge <file>` |
| `status` | Compares the code with the commit the onboarding was generated from: outdated items, deleted evidence, new uncovered files and reader feedback, plus a prompt for the AI. `--fix` fixes evidence that only moved; `--ai` sends the prompt to the installed AI |
| `agents` | Teaches your AI to keep the onboarding up to date (`AGENTS.md`, `CLAUDE.md`, Copilot instructions, Cursor rule, Claude Code `/onboarding` command) |
| `mcp` | MCP server (stdio) with `onboarding_facts`, `onboarding_status`, `onboarding_validate`, `onboarding_translate` and more |
| `serve` | Opens the presentation at `http://localhost:4321` (`--port`). Shows the project, deck stats, coverage and tracks, and logs each time the AI writes `onboarding.json` |
| `translate` | Translates the onboarding without rereading the code: `--to en` writes only the new or changed texts to `onboarding.en.todo.json`, the AI translates that file, and the next `translate` stores the result in `onboarding.en.json`. `--ai` runs it all with the installed AI |
| `export` | Builds one static HTML file (`--out`, default `onboarding.html`). `--offline` embeds Mermaid and fonts; each track and each translated language becomes its own file (`onboarding.frontend.html`, `onboarding.en.html`) |

CLI messages and generated content default to Portuguese. For English, use `init --lang en` or set `ONBOARDING_KIT_LANG=en`.

## Keeping it up to date

Every claim in `onboarding.json` points to real files, and `meta.commit` records the analyzed commit, so `status` knows exactly what aged:

```bash
npx onboarding-kit status        # what changed, and the prompt for the AI
npx onboarding-kit status --fix  # fixes evidence that only moved lines or was renamed
```

In CI, this workflow annotates broken evidence on the PR and summarizes what may be outdated:

```yaml
name: Onboarding
on: pull_request
jobs:
  onboarding:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v7
        with:
          fetch-depth: 0
      - uses: actions/setup-node@v7
        with:
          node-version: 22
      - run: npx onboarding-kit validate --min-score 60
      - run: npx onboarding-kit status
```

With MCP, the AI calls these as tools and gets structured JSON:

```bash
claude mcp add onboarding-kit -- npx onboarding-kit mcp
```

`onboarding.json` references a JSON Schema (`$schema`), so editors and AIs get autocomplete and validation.

## The presentation

`/onboarding` is a slide tour told from a new hire's point of view: welcome → why → business → product → vocabulary (flip cards and a quiz) → rules → stack → architecture → running locally → house style → Git and workflow → quality → required reading → code tour → gotchas → TODOs → first mission → cheat sheet → finale.

- Navigate with ← →, space, swipe or the colored segments; `O` opens the index. Progress is saved in the browser. Light and dark themes.
- **Search:** `Ctrl/Cmd+K` or `/` searches every slide, accent-insensitive.
- **Deep links:** `/onboarding#/architecture`, `/onboarding#/architecture/2`.
- **Print / PDF:** one slide per page.
- **Code snippets:** tour steps, business rules and gotchas show the cited lines (`file.ts:42`), highlighted.
- **Tracks per role:** with `tracks`, the welcome slide offers frontend, backend, QA… each with only the chapters and subprojects that matter: `/onboarding?track=frontend`.
- **What changed since your last visit**, built from the git history of `onboarding.json`.
- **Confusing?** Each slide has a feedback button. Comments go to `onboarding-feedback.json`, and `status` hands them to the AI. Disable with `feedback: false`.
- **Who to ask:** opt-in with `init --people`. Name, role and channel only; `validate` rejects e-mails and phone numbers.
- Brand colors and logo are picked up from Tailwind, CSS variables, theme files and `public/`.
- The presentation UI speaks English, Portuguese and Spanish, following `meta.language`.
- **Portuguese or English:** the PT | EN switcher in the top bar changes the language (`/onboarding?lang=en`). Translated texts come from `translate`; anything missing stays in the original, with a notice and the command to run. Translation is incremental, so the AI only translates what changed.

## Monorepos

npm, Yarn, Bun and pnpm workspaces, Lerna, Rush and Deno are detected (Turborepo and Nx too), as are plain folders with their own `package.json`. `onboarding.json` starts with `subprojects` prefilled, the presentation draws the dependency graph, and `init` puts the route in the first web app, pointing to the root JSON (`--project apps/admin` to pick another).

## Adapters

| Import | For |
|---|---|
| `onboarding-kit/next` | Next.js (App Router and Pages Router) |
| `onboarding-kit/nest` | NestJS |
| `onboarding-kit/vite` | anything on Vite, including Astro and React Router 7 |
| `onboarding-kit/fetch` | `Request → Response`: Nuxt/h3, SvelteKit, Remix, Hono, Elysia, AdonisJS, Bun.serve, Deno.serve |
| `onboarding-kit/fastify` | Fastify |
| `onboarding-kit/koa` | Koa |
| `onboarding-kit/express` / `onboarding-kit/node` | Express, Connect, Polka, plain `http`, Webpack and Gatsby dev servers |

```ts
// Next.js: app/onboarding/route.ts
import { createOnboardingRoute } from "onboarding-kit/next";
export const runtime = "nodejs";
export const dynamic = "force-dynamic";
export const GET = createOnboardingRoute();
export const POST = GET;

// Express
import { createOnboardingHandler } from "onboarding-kit/express";
app.all("/onboarding", createOnboardingHandler());

// Hono
app.all("/onboarding", (c) => onboarding(c.req.raw));
```

All adapters accept `{ file?, enabled?, password?, feedback? }`; Vite, Fastify, Koa and Nest also accept `path`. `POST` on the same route stores slide feedback.

## Security

- The route is **off when `NODE_ENV=production`**, unless you pass `enabled: true` or set a password.
- `ONBOARDING_PASSWORD` (or `password`) adds HTTP Basic auth (any user name), handy for staging.
- Pages are sent with `noindex` and no cache; all JSON content is escaped.
- `validate` looks for tokens, private keys, JWTs and URLs with credentials.
- Feedback only accepts `application/json`, so cross-site forms can't post to it.
